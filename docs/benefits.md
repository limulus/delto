# Benefits

Provisional — drafted 2026-09-19 to dogfood the "Short readable items" initiative in
`BACKLOG.md`. Where this file lives and how benefits are identified are open questions for
ADR-002 (`∆YQb`).

These are the benefits delto exists to give the people it serves. Every brief in
`docs/briefs/` traces its value to one of them, directly or through other items. They
hold for as long as delto exists, and change only when what delto is for changes. Each has
a stable slug, which briefs use in their `serves:` frontmatter.

## `readable-backlog`

The human overseeing a project can read its backlog quickly, know what is planned and why,
and refer to any item without ambiguity.

## `informed-approval`

The overseer can judge, before effort is spent, whether a piece of work is worth doing and
whether the plan for it is sound.

## `agent-ready-work`

An agent with no prior context can find work that is eligible to start and carry it out
correctly.

## `parallel-work`

Several agents can work from the same backlog at once without colliding or repeating each
other's work.

## `lessons-kept`

What was learned while doing the work is recorded and reaches future sessions.

## `cheap-adoption`

A project can adopt delto, and keep up with changes to it, at low cost and without
surprises.

## `maintainable-delto`

Maintainer-facing. delto's own code and skill stay cheap to change safely.
